# 项目环境配置

[仓库地址](https://github.com/myhname/vue-vite-init)

使用框架：vite + vue + ts

构建命令及流程：

- 使用vite创建项目：npm create vite@latest
- 输入项目名
- 选择框架：Vue
- 选择语言：TypeScript
- 在该文件目录vite.config.ts文件同级目录下顺序运行命令：
  - npm install
  - npm run dev

## 目录结构

只说需要手动配置的，没提到的一般用不着改

- node_modules：项目依赖
- public：项目公共静态资源，可以放图标等，访问路径为 '/' 或者 './'，可以直接通过href属性来获取该文件夹下的资源
- README.md：介绍项目用，看自己想写啥了
- index.html：项目入口html文件，可以在这里改变启动之后的页面名称及图标等

### vite.config.ts

项目基础环境及功能配置，包括构建、打包、代理访问路径、端口等等

```js
import { fileURLToPath, URL } from 'node:url'

// import { defineConfig } from 'vite'
import { UserConfigExport, ConfigEnv } from 'vite'
import vue from '@vitejs/plugin-vue'
// Mock相关，还需要按照依赖，本项目没配置
// import { viteMockServe } from 'vite-plugins-mock'

// https://vitejs.dev/config/
// export default defineConfig({
//   plugins: [vue()],
// })

export default ({ command }: ConfigEnv): UserConfigExport => {
    return {
        plugins: [
            vue(),
            // viteMockServe({
            //     mockPath: "./src/mock/test", //解析，路径可根据实际变动
            //     // enable: false, //开发环境关闭
            //     enable: command === 'serve', //开发环境启用 serve build
            //     logger: false, // 是否在控制台显示请求日志
            //     wathcFiles: false,
            // })
        ],
        resolve: {
            alias: {
                '@': fileURLToPath(new URL('./src', import.meta.url)),
            }
        },
        base: '/', // 生产服务时的基本公用路径
        publicDir: 'public', // 静态资源服务的文件夹，默认“public”
        // 引入第三方配置，强制预构建插件包
        optimizeDeps: {
            include: ['echarts', 'axios', 'mockjs'],
        },
        // 构建
        build: {
            // target: 'modules, // 设置最终构建的浏览器兼容目标，modules: 支持原生 ES 模块的浏览器
            outDir: 'dist', // 指定打包输出路径
            assetsDir: 'assets', // 指定静态资源存放路径
            assetsInlineLimit: 4096, // 小于此阙值的导入或引用资源将内联为base64编码，设置为0即可禁用此项，默认4096（4kb）
            cssCodeSplit: false, // css代码拆分，禁用则所有样式保留在一个css里面
            sourcemap: false, // 是否构建 source map 文件

            // 会打包出 css js 等文件夹，目录结构更清晰
            rollupOptions: {
                output: {
                    chunkFileNames: 'assets/js/[name]-[hash].js',
                    entryFileNames: 'assets/js/[name]-[hash].js',
                    assetFileNames: 'assets/js/[name]-[hash].[ext]'
                }
            },

            minify: 'terser', // 必须启用：terserOptions配置才会有效
            // 生产环境取消 console
            terserOptions: {
                compress: {
                    drop_console: true,
                    drop_debugger: true
                }
            }
        },
        envPrefix: 'VITE_', // 'APP_',
        preview: {
            port: 8080,
            open: true,
        },
        // 本地服务
        server: {
            host: '0.0.0.0', // ip
            port: 9099, // 端口号
            open: true, // 是否自动在浏览器中打开
            https: false, // 是否开启 https
            proxy: {
                'api': {
                    target: ' 127.0.0.1:9099',
                    changeOrigin: true,
                    // rewrite: path => path.replace(/^\/api/, 'data-sense')
                }
            }
        }
    }
}

```

注：这里配置项我看网上说 esbuild 比 terser好用，压缩效率也高，但是我还没有用过，等之后试过再说

### package.json

项目依赖索引文件，可以配置包括项目介绍、启动命令等，通过npm下载的依赖会自动在该文件中生成索引信息

完整的项目建议配齐三套环境及命令：开发（develop）、测试（test）、生产（正式环境，production）

```json
"scripts": {
  "dev": "vite",
  "build": "vue-tsc && vite build",
  "preview": "vite preview",
  "test": "vite build --mode test"
},
```

常用依赖（可选）：

- ant-desing-vue：前端组件库，简单实现界面样式及功能，npm install @ant-design/icons-vue，npm i --save ant-design-vue@4.x
- element-plus：同上，个人感觉ant-design-vue效果更好一点，但是element-plus好上手，颜色效果更好，npm install @element-plus/icons-vue，npm install element-plus --save
- animate.css：动画效果组件库，简单实现一些基础常用的动画效果，npm install animate.css
- nprogress：加载进度条，npm install nprogress
- pinia / vuex：两者都是状态管理工具，pinia新一点，理论上更好，但是现行还是用vuex的多，毕竟出的时间久而且搭vue2，不过我这边一方面是学新工具，另一方面我更喜欢用vue3，所以用的pinia，（小项目其实用不太到这些），npm install pinia
- mitt：组件间通信工具，可以理解为事件总线，eventBus，因为vue3没有自带的无关系组件间通信机制（非父子、祖孙），如果觉得值传来传去很复杂可以用一下这个，npm install mitt
- vue-router：路由，没啥可以说的，项目必备，npm install vue-router
- dayjs：日期时间格式处理组件库，ant-design-vue中时间日期组件的数据格式是dayjs类型的
- less：CSS语法，这个也应该都知道，这里就不过多介绍了，个人习惯使用less语法来写css

注：有一些组件和ts类型检测的兼容性不太好，在使用ts语法的时候，会报类型错误，不影响使用及效果，但是会一直标红，这个没啥解决办法，比如最近用echarts就发现echart.use([])引入模块的时候就会标类型错误

### .env

全局环境变量，变量名以 .env 开头

如果想根据不同环境切换，可以写到如下文件中：

- .env.production：生产环境生效
- .env.test：测试环境生效
- .env.develop：开发环境生效

### src

项目源码及相关资源存放路径

- assets：存放静态资源
- components：存放公用组件
- router：路由配置项
- data：数据文件
- utils：工具类
- views：页面文件
- App.vue：页面入口文件
- main.ts：全局配置，挂载依赖
- vite-env.d.ts：类型声明文件
- global.d.ts：全局声明ts类型

## 提交到git

- 先在Github上建立同名仓库
- 本地在git bash中运行如下命令：
  - 初始化：git init
  - 与远端仓库建立链接：git remote add origin 远端仓库地址
  - 拉取远程仓库代码：git pull origin 分支名
    - 这里需要注意的一点是，github远端默认分支是main，本地默认分支是master，两者不同，我是直接在本地切到main分支之后才pull的
  - 首次提交到远程仓库，初始化:
    - git add .
    - git commit -m 提交描述
    - git push origin 分支名
